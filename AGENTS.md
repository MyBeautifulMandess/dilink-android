# AGENTS.md — DI Link (Android)

Документ для агентов и для людей, которые скачали репозиторий. Здесь описано,
как собрать DI Link, где лежит каждая функция и по каким правилам её менять.

Соседний проект — **Dynamic Island for Windows** (островок на компьютере):
<https://github.com/MyBeautifulMandess/dynamic-island-windows>. Телефон и островок
общаются по своему протоколу; при изменении сообщений правки идут в оба
репозитория сразу.

---

## 1. Что это

DI Link — приложение-спутник островка на Windows. Оно умеет:

- сопрягаться с компьютером по QR-коду, вставке ссылки или вручную;
- показывать календарь и напоминания, синхронизировать их с компьютером;
- присылать уведомления Android на островок;
- отправлять и принимать файлы (картинки сразу попадают в галерею);
- отдавать состояние медиаплеера и текст буфера обмена.

Стек: Kotlin, Android Gradle Plugin, Material 3, `ViewBinding`,
без сторонних библиотек (включая сканер QR — используется системная камера).
`minSdk = 24` (Android 7.0), `targetSdk = 34`.

## 2. Требования и быстрый старт

| Что | Нужно |
|---|---|
| Сборка | JDK 17, Android SDK 34, Gradle Wrapper из репозитория |
| Устройство | Android 7.0 или новее |
| Связь | общая Wi-Fi сеть с компьютером (порт 19532) **или** сопряжение по Bluetooth |

```bash
git clone https://github.com/MyBeautifulMandess/dilink-android.git
cd dilink-android
./gradlew :app:assembleDebug          # обычная сборка
./gradlew :app:testDebugUnitTest      # юнит-тесты
./gradlew :app:assembleRelease        # подписанный APK
```

Готовый APK: `app/build/outputs/apk/release/app-release.apk`.

Подпись релиза берётся из `keystore.properties` (файл в `.gitignore`).
Без него сборка выходит неподписанной — для установки на телефон нужен
подписанный ключ.

## 3. Карта репозитория

```
app/src/main/java/com/dynamicisland/dilink/
  LinkApp.kt              Application: каналы уведомлений, доступ к уведомлениям
  link/                   транспорт и протокол
  planner/                календарь и напоминания, общие с компьютером
  reminder/               будильники, уведомления, защита от повторов
  notify/                 доступ к уведомлениям Android
  media/                  мост состояния плеера
  store/                  настройки
  ui/                     экраны и адаптеры
  util/                   Observable, Debounce
app/src/main/res/         разметка, темы, цвета, иконки
app/src/test/             юнит-тесты
```

### 3.1. `link/` — связь с компьютером

| Файл | Ответственность |
|---|---|
| `Protocol.kt` | формат сообщений: `Envelope`, разбор и сборка JSON, `clamp` |
| `LinkClient.kt` | клиент каналов: по каналу на транспорт (Wi-Fi и Bluetooth одновременно), авторизация ключом, очередь при отсутствии связи, своё переподключение у каждого канала |
| `LinkTransport.kt` | общий интерфейс транспорта и WebSocket-реализация поверх OkHttp |
| `BluetoothTransport.kt` | RFCOMM-клиент: подключается к службе компьютера, кадры «вид + длина», запасной транспорт |
| `BluetoothPairing.kt` | знакомство без камеры: поиск компьютера рядом, рукопожатие `pairing.hello` → `pairing.offer` |
| `BtFrames.kt` | кадры Bluetooth: пятибайтовый заголовок «вид + длина» |
| `DeviceIdentity.kt` | имя телефона, постоянный идентификатор установки и аппаратный признак `hwid` (нужны компьютеру, чтобы не заводить копии устройства) |
| `Pairing.kt` | разбор ссылки сопряжения: `dilink://`, http-страница, голый адрес, `bta` (MAC компьютера) |
| `LinkService.kt` | foreground-служба: состояние канала, маршрутизация сообщений, приём и отправка файлов, автозакрытие по простою, замки пробуждения |
| `FileTransfer.kt` | обмен файлами: приём в `.part`, отправка чанками, прогресс |
| `GallerySaver.kt` | сохранение картинок с компьютера в галерею (`MediaStore`) |
| `ClipboardMonitor.kt` | наблюдение за буфером обмена |
| `IdlePolicy.kt` | чистое правило «отключаться по простою» (покрыто тестом) |

### 3.2. `planner/` — календарь и напоминания

| Файл | Ответственность |
|---|---|
| `PlannerRecord.kt` | запись в формате, общем с компьютером (`camelCase`, время в мс Unix) |
| `PlannerStore.kt` | локальное хранилище: JSON-файл, надгробия удалений, слияние «новее — побеждает» |
| `PlannerRepository.kt` | единая точка доступа к хранилищу + наблюдатели |
| `PlannerDays.kt` | правило «событие попадает на день» — используется сеткой календаря и списком дня |

### 3.3. `reminder/` — напоминания

| Файл | Ответственность |
|---|---|
| `ReminderScheduler.kt` | постановка точных будильников через `AlarmManager`, выбор ближайшего срока |
| `ReminderNotifier.kt` | уведомление о наступившем сроке |
| `ReminderReconciler.kt` | пересборка будильников и уведомлений после изменения записей |
| `NotifiedStore.kt` | учёт уже показанных сроков — чтобы уведомление не приходило дважды |

### 3.4. `ui/` — экраны

| Файл | Ответственность |
|---|---|
| `MainActivity.kt` | четыре вкладки: Связь, Календарь, Напоминания, Настройки |
| `LinkLinkFragment.kt` | сопряжение, состояние канала, список передач, отправка файлов и буфера |
| `BluetoothPairing.kt` (в `link/`) | поиск компьютера рядом и рукопожатие — вызывается из `LinkLinkFragment` |
| `CalendarFragment.kt` | месячная сетка и события выбранного дня |
| `MonthGrid.kt` | сетка месяца: 7 колонок, понедельник первым, отметки дней с событиями |
| `ReminderFragment.kt` | список напоминаний, отметка «выполнено» |
| `PlannerAdapter.kt` | карточка записи, общая для календаря и напоминаний |
| `TransferAdapter.kt` | строка передачи: прогресс, путь, кнопки «Открыть» и «Где лежит» |
| `SettingsFragment.kt` | переключатели синхронизации, доступы, исключения приложений |
| `ShareActivity.kt` | отправка файла из «Поделиться» |

### 3.5. Остальное

- `notify/NotificationRelay.kt` — `NotificationListenerService`: читает уведомления Android
  и отдаёт их островку.
- `media/MediaBridge.kt` — состояние и команды медиаплеера.
- `store/Settings.kt` — настройки в `SharedPreferences`.
- `util/Observable.kt` — простая наблюдаемость без библиотек.

## 4. Протокол «островок ↔ телефон`

Формат кадра — JSON: `{"type": "...", "id": "...", "payload": {...}}`.
Авторизация — общим ключом: одноразовым из QR при первой встрече и постоянным
после `auth.ok`. Порт компьютера 19532 — только для Wi-Fi; Bluetooth идёт поверх
службы RFCOMM с UUID `6e400001-b5a3-f393-e0a9-e50e24dcca9e`, которую публикует
компьютер. В RFCOMM кадр несёт пятибайтовый заголовок: вид (1 — текст,
2 — данные) и длина big-endian.

| Тип | Назначение |
|---|---|
| `auth` / `auth.ok` / `auth.rejected` | вход по ключу; в `auth` телефон шлёт `name`, `instance` и аппаратный `hwid`, в `auth.ok` приходит постоянный `token` |
| `pairing.hello` / `pairing.offer` / `pairing.rejected` | знакомство без камеры: телефон просит ключ, компьютер спрашивает разрешение и отвечает `pairing.offer` (одноразовый `token`, `ip`, `port`, `bta`) |
| `ping` / `pong` | проверка живости канала; `pong` уходит тем же каналом, по которому пришёл `ping` |
| `clipboard.push` | текст буфера обмена |
| `notification.push` / `notify.dismissed` | уведомления Android |
| `media.state` / `media.command` | медиаплеер |
| `file.offer` / `file.chunk` / `file.done` / `file.ack` / `file.cancel` | файлы; данные идут бинарными кадрами после `file.chunk` |
| `planner.push` / `planner.sync` | календарь и напоминания; `sync` — полный снимок |

**Правило:** новое сообщение добавляется в обеих реализациях сразу —
`link/Protocol.kt` (телефон) и `Services/PhoneProtocol.cs` (островок).

## 5. Как добавить или изменить функцию

### Экран или вкладка

1. Разметка — `app/src/main/res/layout/fragment_*.xml`, стили — `values/themes.xml`
   (`Widget_DiLink_*`, `Text_DiLink_*`), цвета — `values/colors.xml`.
2. Фрагмент — `ui/`, доступ к данным через `LinkService.instance` или
   `PlannerRepository`.
3. Строки — только в `values/strings.xml`.

### Новая функция связи

1. Новый тип сообщения — в `link/Protocol.kt` и в `Services/PhoneProtocol.cs`.
2. Обработка в `LinkService.handle()` и отправка через `LinkService.send()`.
3. Если сообщение нужно копить при отсутствии связи — это уже умеет `LinkClient`.
4. Транспорт не важен: `LinkClient` работает через `LinkTransport`, поэтому
   функция одинаково живёт на Wi-Fi и Bluetooth. Ничего не дублируется по каналам.
5. Держите оба канала одновременно: `LinkClient` не вытесняет один транспорт
   другим. Вытеснение уже приводило к «миганию» связи.

### Запись календаря или напоминания

1. Формат — `planner/PlannerRecord.kt` и `Models/PlannerRecord.cs` на компьютере.
2. После изменения записи — `ReminderReconciler.sync(context)`: будильники и
   уведомления пересобираются заново.
3. Удаление — только надгробием (`deleted = true`), иначе запись вернётся
   с компьютера при следующей синхронизации.

## 6. Правила стиля

- Язык интерфейса и комментариев — русский.
- Комментарий объясняет **почему**, а не что делает код.
- Стиль именования Kotlin — как в существующих файлах: `object` для чистых
  правил, `class` для состояния, `internal` для внутренних деталей.
- Никаких новых зависимостей без необходимости: APK должен оставаться маленьким,
  сканер QR не нужен — работает системная камера.
- Разрешения запрашиваются лениво и только там, где без них нельзя:
  камера не используется вовсе. Для поиска компьютера нужны `BLUETOOTH_SCAN`
  и `BLUETOOTH_CONNECT` (Android 12+), на Android 10–11 — доступ к
  местоположению; на старых версиях ничего спрашивать не нужно.
- Поиск устройств и рукопожатие идут в отдельном потоке: `BluetoothSocket`
  не умеет таймаут, поэтому разговор ограничен по времени вручную.
- Не терять постоянный ключ из `auth.ok`: без него телефон вернётся к
  одноразовому коду, и компьютер заведёт ещё одну запись устройства.
- Не терять `instance` из `pairing.hello`: по нему компьютер узнаёт, что это
  тот же телефон, и не заводит вторую запись устройства.
- Не отключать канал по простою, пока жив Bluetooth: сокет сам сообщит об
  обрыве, а автозакрытие по времени рвёт связь на пустом месте.
- Не закрывать второй канал при появлении первого: Wi-Fi и Bluetooth работают
  параллельно, и оба нужны — иначе связь мигает при каждом переподключении.
- `ping` подтверждать тем же каналом, по которому он пришёл. Ответ «лучшим»
  транспортом оставлял Bluetooth молчащим, и компьютер закрывал его по таймауту.
- `WakeLock` брать без таймаута: ограниченный замок тихо истекает, и канал
  засыпает вместе с экраном.
- Не отправлять чанки файла, не дожидаясь `file.ack`: на Bluetooth очередь
  растёт быстрее, чем уходит в сокет, и канал захлёбывается.
- Секреты (ключ сопряжения) не пишутся в лог.

## 7. Проверка перед коммитом

1. `./gradlew :app:testDebugUnitTest` — все тесты зелёные.
2. `./gradlew :app:assembleRelease` — APK собирается.
3. На устройстве: сопряжение по QR и по Bluetooth («Найти компьютер» —
   компьютер спросит разрешение), буфер в обе стороны, уведомления доходят
   до островка, файл с компьютера попадает в галерею (картинка) или в
   `Download/DI Link` (остальное), открывается кнопкой «Открыть».
4. Напоминание: создать, дождаться срока, убедиться, что уведомление пришло
   **ровно один раз** (защита `NotifiedStore`).
5. Выключить компьютер из сети, создать запись — она должна сохраниться локально
   и уйти при подключении.

## 8. Релиз

1. Поднять `versionCode` и `versionName` в `app/build.gradle.kts`, строку
   `version_line` в `values/strings.xml`.
2. Обновить README: раздел «Что нового в X.Y.Z», ссылка на APK.
3. `./gradlew :app:assembleRelease`, проверить подпись:
   `apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk`.
4. Закоммитить, отметить тег `vX.Y.Z`, создать релиз на GitHub с APK.
5. Сверить SHA-256 скачанного APK и локального.

### Ключ подписи

Релизы подписываются ключом **`dilink-release.jks`** (alias `dilink`,
RSA 2048, срок 10 000 дней, `CN=DI Link, OU=Dynamic Island, O=Dynamic Island,
L=Moscow, C=RU`).

| Что | Где |
|---|---|
| Ключ и пароль (рабочая копия) | корень клона репозитория: `dilink-release.jks` + `keystore.properties` — оба в `.gitignore` |
| Резервная копия | `C:\Users\erizo\Documents\DI-Link-signing\` (`dilink-release.jks`, `keystore.properties`) |
| SHA-256 сертификата | `e2897264c2b7ac779c1662ee230328ac064dd155a9e9c52da37406c811990741` |

- Пароль лежит только в `keystore.properties` рядом с ключом. В репозиторий,
  README и логи он не попадает.
- **Не пересоздавать ключ и не менять alias.** Android ставит обновление только
  поверх сборки с той же подписью. Новый ключ означает для пользователей
  удаление приложения и потерю настроек.
- Если `keystore.properties` нет, `assembleRelease` соберёт неподписанный APK —
  проверяйте `apksigner verify` перед публикацией.
- Ключи прежних релизов (1.5.0–1.6.0, сертификат `52c0…8303`) утрачены; 1.8.2 —
  первый релиз на текущем ключе, поэтому переход на него требует одной
  переустановки.

## 9. Чего делать нельзя

- Не менять формат сообщений протокола в одной из сторон.
- Не отправлять уведомление о напоминании повторно — пользователь уже жаловался
  на «бомбинг»; за это отвечает `NotifiedStore`.
- Не требовать разрешение на камеру: QR открывается системной камерой.
- Не хранить файлы вне приватной папки приложения без явной нужды.
- Не терять постоянный ключ из `auth.ok`: без него телефон вернётся к
  одноразовому коду, и компьютер заведёт ещё одну запись устройства.
- Не забывать, что с Android 10+ запись в галерею делается через `MediaStore`,
  а на 7–9 — копированием в `Pictures/DI Link` с `MediaScannerConnection`.
